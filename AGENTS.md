# Zupflow monorepo

Read `README.md` first.

## Ground rules

- **The API contract lives in `@zupflow/contract`**: one zod schema per
  request and response (`schemas.ts`), one entry per endpoint (`routes.ts`),
  and the generated `openapi.json`. Types everywhere are inferred from it.
  When a screen needs data the API doesn't provide, change the contract first
  (`pnpm --filter @zupflow/contract generate` refreshes `openapi.json`), then
  the SDK's `client.ts`, then the mock handler (with a test), then the hook,
  then the page, in that order. The mock's tests check every response
  against the contract.
- **The mock API is the backend's specification until the backend exists.**
  Rules it enforces are product rules. Don't loosen one to make a screen
  easier; add a test when you add one. A case that needs only the API goes in
  the shared suite, `packages/contract-tests/src/suite.ts`, which the backend
  must pass too; one that has to reach into the mock's database goes in
  `apps/console/src/mocks/handlers.test.ts`.
- **Every change checks a role.** Each mutating Console route calls
  `requireRole` right after resolving access: `DEVELOPERS` (every role but
  `viewer`) or stricter. The exceptions have no member role to check:
  creating one's own organization, API-key-only routes (approvals) and hosted
  Connect, which the session's reference authorizes. The shared suite tries
  every Console-callable change as a viewer (all refused) and as a developer
  (only the named admin- and owner-only ones refused), and fails if a
  mutating route is missing from its list.
- **Idempotency is one wrapper.** Every `POST` goes through it
  (`apps/console/src/mocks/idempotency.ts`, from `route`); never read
  `Idempotency-Key` in a handler. A route whose response shows a secret once
  is marked `showsSecretOnce` in the contract, so its body is never saved.
- **Two layers of isolation.** No organization reaches another, and no
  workspace reaches another within its organization. Both scopes are explicit
  in every function, table, query, key and test; a globally unique ID never
  substitutes for either.
- **Environment is a workspace property, fixed at creation.** Never fall back
  from one environment's configuration to the other's.
- **Never load every workspace.** Organizations have thousands. Lists page and
  search on the server; pickers and ⌘K query as you type.
- **The Console observes approvals; it never resolves them.** The downstream
  user decides in the customer's product.
- **The Console doesn't act in Production.** No starting runs or connecting
  accounts there; the customer's product does that through the API.
- **Every external resource is a trait.** Database, cache, storage, keys,
  queues, events, compute. This repository ships only basic implementations
  (SQLite, in-memory, local files, local keys); no provider implementations,
  vendor configuration or credentials.
- **Zupflow stands alone.** No client, partner or other product is named in
  code, data, docs, commits or pull requests. Demo data uses fictional
  organizations and `.example` domains.
- **Secrets are write-only.** Responses expose `set` and `last4`, never values.
  A newly created API key or signing secret is shown once from the creating
  response and never stored by the Console.

## Backend conventions (`server/`)

- One Cargo workspace; `pnpm check` runs `cargo fmt --check`, `clippy` with
  warnings denied, `cargo test` and `cargo build` through `@zupflow/server`.
- IDs are `Id<K>` from `zupflow_core::ids` (`WorkspaceId`, `RunId`, …). Never
  format, parse or store a prefixed ID by hand; storage holds the UUID. The
  registry must equal the contract's (a test reads `openapi.json`).
- Scope comes first: organization-scoped functions take the organization ID
  first, workspace-scoped ones the organization then the workspace.
- Errors are `ApiError` (status, stable code, message, fields); responses are
  the envelope. Production code returns errors instead of panicking; no
  `unwrap`, and `expect` only for true invariants with a reason.
- Configuration is `ZUPFLOW_*`; an invalid value stops startup.
- External resources are traits in `zupflow-core`; the basic implementations
  live in `zupflow-basic` and run their trait's suite from
  `zupflow-conformance`. A new implementation isn't done until it passes; a
  new rule for a trait goes into its suite, not only into one implementation.
- Secrets are sealed with `keys::seal` under an `EncryptionContext` built from
  the trust context with the constructor for that kind of secret
  (`installation_credential`, `oauth_client_secret`, `webhook_signing_secret`),
  and opened only by the code that uses them. An installation's credential is
  sealed as one value per version, all its fields together.

## Console conventions

- Data flows SDK → `src/features/queries.ts` → pages. No `fetch` in features.
- shadcn primitives for generic controls. `src/components/ui` is generated by
  the shadcn CLI: don't hand-edit it. After `shadcn add`, check that new files
  import `cn` from `@/lib/utils` (the CLI once resolved it to an npm package).
- Loading states are skeletons shaped like the content, never bare text.
- Every page is usable at 375 px. Tables shrink their first column
  (`w-full max-w-0` + `truncate`) and hide secondary columns; the run table
  uses container queries.
- Copy: sentence case, plain verbs, name things by what people control.
  Errors say what happened and how to fix it.
- `src/routeTree.gen.ts` is generated by the TanStack Router plugin. Commit it;
  don't edit it.

## Checks

```bash
pnpm check
```

Lint (Biome), typecheck, tests and build must pass. Verify UI changes in a
browser at desktop and 375 px, in light and dark.
